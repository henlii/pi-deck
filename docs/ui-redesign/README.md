# Pidance UI 重做提案

本目录提供三套可独立落地、也可交叉取长的视觉方向。三套方案均保留 Pidance 的真实信息架构：项目／工作树／会话树、最近会话、中部消息流与工具调用、输入区、右侧文件／Git／会话信息，以及外观／模型／技能／插件／默认值／信任设置。

## 快速预览

直接用浏览器打开各 `.html` 文件即可。设计稿不加载网络字体、脚本或图标资源；稿内用字符占位，实际产品建议继续使用 Lucide React。

| 方向 | 定位 | 适合谁 | 核心视觉决策 |
|---|---|---|---|
| **A · 墨纸工作台** | 安静、编辑感、长时阅读优先 | 日常深度使用、重视内容与层级的开发者 | 用暖灰纸感底色、细墨线和珊瑚红强调，把复杂工具界面做成克制的编辑工作台。 |
| **B · 光谱舱** | 精密、现代、空间感强 | 喜欢 Cursor／Linear 式高效率界面的用户 | 用深靛蓝玻璃层、青绿状态光和不对称轨道，让多面板工作流具有清晰纵深。 |
| **C · 磷光终端** | 高对比、键盘优先、工程气质 | 终端重度用户、追求信息密度与可扫描性的人 | 用黑色底、磷光绿与严格网格，将会话、工具和状态统一为可扫描的控制台语言。 |

## 共同交互原则

1. **聊天是主舞台**：桌面端消息正文控制在舒适行宽内，左右面板均可折叠；面板存在但不抢占阅读注意力。
2. **最近会话是快捷入口而非第二棵树**：固定在项目树上方，只显示跨项目最近活动，项目树继续承担完整层级浏览。
3. **工具调用默认摘要、按需展开**：状态、动作、耗时和改动量一眼可见；终端输出和 diff 在展开后阅读。
4. **移动端单手优先**：底栏放置会话、聊天、文件、更多四个一级入口；输入与发送处于拇指热区，项目树和右栏转为全屏抽屉。
5. **模式与主题正交**：`theme` 决定气质，`mode` 决定明暗；支持浅色、深色、跟随系统，切换时不改变信息密度。
6. **状态不只靠颜色**：运行、成功、警告、失败同时使用图形／文字／颜色，满足高对比和色觉差异需求。

## 建议的产品路线

优先采用 **A 的阅读布局与消息表达**、**B 的面板纵深和状态设计**、**C 的高密度工具卡片**。若必须整套选择，建议以 **A · 墨纸工作台** 作为默认主题，B、C 作为可选主题；它对浅／深模式都稳定，也最适合长时间对话阅读。
